# Green Web 后端接口文档

本文档基于 Green Web 前端项目需求，规划并定义了后端系统的技术架构、API 接口规范及数据模型。

## 1. 项目概述

**项目名称**: Green Web Backend  
**项目描述**: 为 Green Web 前端提供数据持久化、业务逻辑处理及 AI 模型接口转发服务。核心功能包括用户认证、社区互动、AI 助手对话管理及旧物重构分析。  
**版本**: 0.0.1 (Draft)

## 2. 推荐技术栈 (Recommended Tech Stack)

为配合前端 Vue 3 + Vite 的现代化架构，建议后端采用以下技术栈：

*   **开发语言**: Node.js (v18+)
*   **Web 框架**: Express
*   **数据库**: MySQL 8.0+ (关系型数据) + Redis (缓存与会话)
*   **ORM**: Sequelize 或 TypeORM
*   **对象存储**: AWS S3 / Aliyun OSS (存储社区图片及用户上传的旧物图片)
*   **AI 集成**: OpenAI SDK (Node.js) / LangChain (对接 SiliconFlow GLM-4.7)

## 3. 接口规范 (API Specification)

*   **Base URL**: `/api/v1`
*   **数据格式**: JSON
*   **认证方式**: JWT (JSON Web Token) - `Authorization: Bearer <token>`

### 3.1 用户认证 (Auth)

#### 3.1.1 注册 (Local)
*   **URL**: `POST /auth/register`
*   **描述**: 创建新用户账号。
*   **Request Body**:
    ```json
    {
      "email": "user@example.com",
      "password": "securepassword123",
      "username": "GreenHero"
    }
    ```
*   **Response (201 Created)**:
    ```json
    {
      "user_id": "12345",
      "email": "user@example.com",
      "message": "注册成功"
    }
    ```

#### 3.1.2 登录 (Local)
*   **URL**: `POST /auth/login`
*   **描述**: 用户登录并获取 Token。
*   **Request Body**:
    ```json
    {
      "email": "user@example.com",
      "password": "securepassword123"
    }
    ```
*   **Response (200 OK)**:
    ```json
    {
      "access_token": "eyJhbGciOiJIUz...",
      "token_type": "bearer",
      "expires_in": 3600,
      "user": {
        "id": "12345",
        "username": "GreenHero",
        "avatar": "url/to/avatar.jpg"
      }
    }
    ```

#### 3.1.3 Google 登录
*   **URL**: `GET /auth/google`
*   **描述**: 重定向至 Google 授权页面。
*   **Callback URL**: `GET /auth/google/callback`
*   **Response**: 重定向回前端页面，携带 token (e.g., `http://localhost:5173/auth/callback?token=...`)

#### 3.1.4 Outlook/Microsoft 登录
*   **URL**: `GET /auth/microsoft`
*   **描述**: 重定向至 Microsoft 授权页面。
*   **Callback URL**: `GET /auth/microsoft/callback`
*   **Response**: 重定向回前端页面，携带 token (e.g., `http://localhost:5173/auth/callback?token=...`)

### 3.2 用户信息 (User)

#### 3.2.1 获取当前用户信息
*   **URL**: `GET /users/me`
*   **认证**: Required
*   **Response (200 OK)**:
    ```json
    {
      "id": "12345",
      "username": "GreenHero",
      "email": "user@example.com",
      "points": 120,
      "level": 2,
      "badges": [
        { "id": "b01", "name": "环保先锋", "icon_url": "..." }
      ]
    }
    ```

#### 3.2.2 更新积分 (内部调用或特定行为触发)
*   **URL**: `POST /users/me/points`
*   **认证**: Required
*   **描述**: 增加用户积分（如完成任务）。
*   **Request Body**:
    ```json
    {
      "amount": 10,
      "reason": "completed_daily_quiz"
    }
    ```

### 3.3 AI 助手 (Chat)

#### 3.3.1 发送对话消息
*   **URL**: `POST /chat/completions`
*   **认证**: Required
*   **描述**: 转发请求至 GLM-4.7 模型，支持流式返回。后端负责隐藏 API Key 并存储对话记录。
*   **Request Body**:
    ```json
    {
      "messages": [
        { "role": "user", "content": "如何减少塑料使用？" }
      ],
      "stream": true
    }
    ```
*   **Response**: Server-Sent Events (SSE) stream.

#### 3.3.2 获取历史记录
*   **URL**: `GET /chat/history`
*   **认证**: Required
*   **Response (200 OK)**:
    ```json
    [
      {
        "id": "msg_001",
        "role": "user",
        "content": "如何减少塑料使用？",
        "created_at": "2023-10-27T10:00:00Z"
      },
      {
        "id": "msg_002",
        "role": "assistant",
        "content": "您可以尝试使用布袋...",
        "created_at": "2023-10-27T10:00:05Z"
      }
    ]
    ```

### 3.4 社区互动 (Community)

#### 3.4.1 获取动态列表 (Feed)
*   **URL**: `GET /community/posts`
*   **参数**:
    *   `page`: 页码 (默认 1)
    *   `limit`: 每页数量 (默认 10)
    *   `sort`: 排序方式 (latest/popular)
*   **Response (200 OK)**:
    ```json
    {
      "items": [
        {
          "id": "post_101",
          "author": { "id": "123", "username": "EcoUser" },
          "content": "今天把旧牛仔裤改成了包包！",
          "images": ["url1.jpg", "url2.jpg"],
          "likes_count": 56,
          "comments_count": 12,
          "is_liked": false,
          "created_at": "..."
        }
      ],
      "total": 100,
      "page": 1
    }
    ```

#### 3.4.2 发布动态
*   **URL**: `POST /community/posts`
*   **认证**: Required
*   **Request Body**:
    ```json
    {
      "content": "分享我的环保心得...",
      "image_urls": ["http://oss.example.com/img1.jpg"]
    }
    ```

#### 3.4.3 点赞/取消点赞
*   **URL**: `POST /community/posts/{post_id}/like`
*   **认证**: Required
*   **Response**: `{"status": "liked", "count": 57}`

### 3.5 旧物重构 (Reconstruction)

#### 3.5.1 上传图片并分析
*   **URL**: `POST /reconstruction/analyze`
*   **认证**: Required
*   **Content-Type**: `multipart/form-data`
*   **Form Data**:
    *   `file`: (Binary Image Data)
*   **描述**: 上传图片至对象存储，并调用多模态 AI 模型（如 GLM-4V）分析图片内容，生成改造建议。
*   **Response (200 OK)**:
    ```json
    {
      "analysis_id": "rec_999",
      "image_url": "http://oss.example.com/uploads/old_chair.jpg",
      "material": "木质",
      "suggestions": [
        {
          "title": "复古花架",
          "steps": ["打磨", "刷漆", "组装"],
          "difficulty": "Medium",
          "carbon_reduction": "5.2kg"
        }
      ]
    }
    ```

## 4. 数据库设计概要 (Database Schema)

### Users 表
*   `id`: UUID, Primary Key
*   `email`: String, Unique
*   `password_hash`: String
*   `username`: String
*   `points`: Integer (Default 0)
*   `created_at`: Timestamp

### Badges 表
*   `id`: String, Primary Key
*   `name`: String
*   `description`: String
*   `icon_url`: String

### UserBadges 表 (关联表)
*   `user_id`: UUID, FK
*   `badge_id`: String, FK
*   `unlocked_at`: Timestamp

### Posts 表
*   `id`: UUID, Primary Key
*   `user_id`: UUID, FK
*   `content`: Text
*   `images`: JSON Array (存储图片 URL)
*   `likes_count`: Integer
*   `created_at`: Timestamp

### ChatHistory 表
*   `id`: UUID, Primary Key
*   `user_id`: UUID, FK
*   `role`: String (user/assistant)
*   `content`: Text
*   `created_at`: Timestamp

## 5. 错误码规范 (Error Codes)

| HTTP Code | Error Code | Description |
| :--- | :--- | :--- |
| 400 | `INVALID_PARAM` | 请求参数错误 |
| 401 | `UNAUTHORIZED` | 未登录或 Token 过期 |
| 403 | `FORBIDDEN` | 无权限执行此操作 |
| 404 | `NOT_FOUND` | 资源未找到 |
| 413 | `FILE_TOO_LARGE` | 上传文件超过限制 (5MB) |
| 429 | `RATE_LIMIT` | 请求过于频繁 |
| 500 | `INTERNAL_ERROR` | 服务器内部错误 |
